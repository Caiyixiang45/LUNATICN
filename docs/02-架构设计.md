# 02 架构设计

## 一、总体结构

```
+--------------------+        HTTP/WS (JSON)        +----------------------+
|  Python 客户端      | <--------------------------> |  社区服务端 (Go)      |
|  client/           |                              |  server/             |
+---------+----------+                              +-----+----------------+
          |                                               |
          | 启动/停止进程                                   | 守护进程
          v                                               v
+--------------------+        UDP/TCP 30000+        +----------------------+
|  Luanti 引擎        | <--------------------------> |  固定服务器 / roomd   |
|  (官方便携版)        |   玩家客户端互联              |  (独立公开项目)        |
+--------------------+                              +----------------------+
```

三条边界清晰：

1. **启动器 ↔ 社区服务端**：纯 HTTP/JSON + WebSocket，启动器不直连数据库。
2. **启动器 ↔ 引擎**：子进程托管，参数传递，日志回读。
3. **roomd ↔ 社区服务端**：roomd 作为客户端注册房间并打心跳，社区服务端只是注册中心；roomd 也可脱离社区服务端单机运行。

## 二、启动器分层（launcher/LUNATICN）

```
Views/        XAML 页面 + 代码后置（Lobby/Worlds/Mods/Workshop/Friends/Settings/LoginDialog）
Services/     AppServices(单例装配) ApiClient(后端) EngineManager(引擎托管)
              WorldService ModService PackageBuilder RoomHostService(开房+加入)
Models/       RoomInfo ServerInfo PackageInfo FriendInfo UserInfo 等纯数据模型
```

约定：

- 页面不直接 new 服务，一律 `AppServices.Instance.*` 取单例。
- 后端 JSON 统一 snake_case（`JsonNamingPolicy.SnakeCaseLower`），与 Go 端 `json:"..."` 标签一一对应。
- 所有网络方法返回 `Result<T>`，成功/失败带错误文本，不向上抛裸异常。

## 三、社区服务端模块（server）

| 包 | 职责 |
|----|------|
| `cmd/server` | 入口：加载配置、装配、优雅退出 |
| `internal/config` | JSON 配置加载与校验 |
| `internal/store` | 单文件 JSON 存储（用户、好友、包元数据），带锁，零外部依赖 |
| `internal/auth` | argon2id 密码哈希、JWT 签发/校验/刷新 |
| `internal/lobby` | 房间 Hub：注册、心跳、超时清扫、按好友关系过滤、广播变更 |
| `internal/packages` | 分享包存储：上传落盘、检索、配额（单包上限 512MB 级） |
| `internal/fixedserver` | 固定服守护：启动、监控、崩溃拉起 |
| `internal/api` | 路由、全部 handler、WebSocket 推送 |

### 数据存储

`data/` 目录下：

```
data/
  store.json        用户、好友、包索引（原子写：临时文件+rename）
  packages/         分享包文件与缩略图
  uploads/          上传临时目录
```

选型理由：私有部署规模小，单文件存储免去数据库运维；所有写操作经互斥锁串行化。

## 四、实时推送

`GET /api/ws` 升级 WebSocket，服务端在房间状态变化（注册/心跳人数变化/注销/超时）时向全部在线连接广播：

```json
{ "type": "rooms" }
```

客户端收到后重新拉取 `GET /api/rooms`，避免增量同步的复杂度。

## 五、联机模型

- **房主开服**：启动器 `RoomHostService` 拉起 `luanti --server`，向社区服务端注册房间并按 10s 间隔心跳；关闭时注销。房间信息里 `source=launcher`。
- **固定服务器**：社区服务端 `fixedserver.Manager` 按配置常驻拉起若干 `luanti --server`，进程退出即重启；房间信息里 `source=fixed`，启动器单独展示在"官方服务器"页签。
- **加入方**：拿到 host:port 后由 `JoinService` 启动 `luanti --go --address host --port port`。

## 六、分享包链路

```
本地世界/模组 --PackageBuilder--> .lnpkg(zip) --POST /api/packages--> 服务端落盘+索引
工坊检索 <--GET /api/packages-- 服务端 <- 关键词/type/分页参数
下载 <--GET /api/packages/{id}/download-- 启动器解包入库(世界或模组)
```

格式详见 [05 分享包格式](05-分享包格式.md)。

## 八、错误处理约定

- HTTP 错误统一 `{"error": "中文说明"}`，状态码 400/401/404/409/500。
- 启动器 `TryExtractError` 优先解析 `error` 字段展示。
- 引擎进程日志逐行回传 UI；进程异常退出时 `HostState.Error` 展示 `LastError`。
