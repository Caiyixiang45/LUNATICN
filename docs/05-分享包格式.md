# 05 分享包格式（.lnpkg）

`.lnpkg` 是地图与模组的统一分发格式，本质是 zip。启动器打包、社区服务端存储、启动器下载后自动入库。

## 一、目录结构

```
mypackage.lnpkg  (zip)
├── manifest.json          包描述（必须）
├── content/               实际内容（必须）
│   ├── ...                地图：世界目录全部文件（world.mt、mapmeta/、blocks/ 等）
│   └── ...                模组：mod.conf、init.lua、textures/ 等
└── thumbnail.png          可选缩略图（当前由上传接口单独提供）
```

约定：

- 路径分隔符统一 `/`，包内禁止 `..` 与绝对路径（防 zip slip）。
- 世界截图 `screenshot.*` 打包时自动排除。
- `manifest.json` 必须存在；`content/` 下必须至少有一个文件。

## 二、manifest.json

snake_case JSON，示例：

```json
{
  "type": "map",
  "name": "雪山生存",
  "author": "player01",
  "version": "1.2.0",
  "description": "带自定义地形的生存地图",
  "gameid": "minetest",
  "engine": "5.16.1",
  "depends": ["schemathings"]
}
```

| 字段 | 必填 | 说明 |
|------|------|------|
| `type` | 是 | `map`（地图）或 `mod`（模组），二者之外校验失败 |
| `name` | 是 | 展示名 |
| `version` | 是 | 语义化版本字符串，展示用 |
| `author` | 否 | 作者用户名（上传时服务端也会写入令牌对应用户） |
| `description` | 否 | 简介，参与关键词检索 |
| `gameid` | 否 | 地图依赖的游戏，如 `minetest`；下载地图后按此创建存档 |
| `engine` | 否 | 打包时使用的引擎版本，仅展示与兼容性提示 |
| `depends` | 否 | 模组硬依赖名列表，下载模组时提示安装 |

## 三、打包与校验（启动器）

`PackageBuilder`：

- `BuildFromWorld(worldDir, manifest, dest)` — `type=map`，把世界目录打进 `content/`。
- `BuildFromMod(modDir, manifest, dest)` — `type=mod`，把模组目录打进 `content/`。
- `Validate(lnpkgPath)` — 上传前自检：结构、路径合法性、`name/version/type`。

序列化使用 `JsonNamingPolicy.SnakeCaseLower`，与服务端 `internal/packages.Manifest` 字段一一对应。

## 四、服务端存储

上传 `POST /api/packages` 后：

1. 解包校验 `manifest.json`（`type` 必须 map/mod）；
2. 文件落盘到 `data/packages/<生成的 id>.lnpkg`，缩略图单独保存；
3. 元数据写入 `store.json` 的 `packages` 索引（id、名称、作者、大小、下载数、时间等）；
4. 单包大小上限 640MB（`http.MaxBytesReader`），检索分页 limit 最大 100。

## 五、下载入库流程

### 地图（type=map）

1. `GET /api/packages/{id}/download` 拉取 `.lnpkg` 到本地缓存；
2. 解压 zip → 定位含 `world.mt` 的目录（支持 `content/` 直接是世界目录或再包一层）；
3. 复制到 `data/worlds/<名字>`（重名自动加后缀）；
4. 存档库立即可见，"进入"时带上 `gameid`。

### 模组（type=mod）

1. 下载到本地缓存；
2. `ModService.InstallZip` 解压进 `data/mods/<mod_name>`（以 `mod.conf` 的 `name` 为准，重名去后缀）；
3. 模组中心出现新模组，可"配置到存档"。

## 六、模组启用与依赖

- 启用/禁用写目标世界 `world.mt`：`load_mod_<mod_name> = true / false`。
- "配置到存档"时调用 `ModService.ResolveDependencies`：
  - 递归收集硬依赖，缺失则提示"缺失依赖: ..."并中止；
  - 返回 `(选中列表, 拓扑加载顺序, 缺失列表)`，加载顺序按依赖拓扑写入；
  - 可选依赖缺失仅提示，不阻断。

## 七、版本兼容

| 情况 | 处理 |
|------|------|
| `engine` 与本地引擎版本不同 | 仍允许下载，仅记录展示；地图一般向后兼容 |
| `gameid` 本地未安装对应游戏 | 下载后世界存在，进入时引擎会提示缺游戏，需先在引擎内下载游戏 |
| `depends` 缺失 | 模组可装，启用时提示缺失依赖 |
| 未来格式变更 | 以 `manifest.json` 是否存在及字段为准做向后兼容 |

## 八、手工制作包

开发者可直接压 zip 改名 `.lnpkg`：

```powershell
# 目录结构准备成 manifest.json + content/... 后：
Compress-Archive -Path manifest.json, content -DestinationPath pkg.zip
Rename-Item pkg.zip pkg.lnpkg
```

服务端与启动器都按结构校验，不校验签名（私有部署场景）。
